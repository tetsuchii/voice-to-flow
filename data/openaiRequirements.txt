# **Comprehensive Digital UI Components & UX Guidelines**

## **1. Navigation & Structure**

### **Navigation Bars / Menus**

- **Purpose / Use:** Primary navigation; guides users through the main sections of an app or website.
- **Best Practices:**
    - Keep visible on all pages (sticky or fixed).
    - Prioritize top-level content, use clear, concise labels.
    - Include visual feedback for active states.
- **Subcomponents:**
    - Logo / Branding
    - Menu Items (text + icon optional)
    - Dropdowns / Flyout menus
    - Search field / Icon
    - User Profile Menu / Avatar
- **UX Examples:** Google Docs top bar, Slack sidebar.

### **Breadcrumbs**

- **Purpose / Use:** Shows location in hierarchy; improves findability.
- **Best Practices:**
    - Only for multi-level content (>2 levels).
    - Clickable links; current page not clickable.
    - Use “>” or “/” separators.
- **Subcomponents:**
    - Home link
    - Intermediate page links
    - Current page indicator
- **UX Examples:** Amazon product categories, Medium article hierarchy.

### **Tabs / Tab Bars**

- **Purpose / Use:** Switch between related views or content categories.
- **Best Practices:**
    - 3–7 tabs max.
    - Highlight active tab visually (underline, color, bold).
    - Keep order consistent across pages.
- **Subcomponents:**
    - Tab label
    - Tab icon (optional)
    - Tab indicator / underline
- **UX Examples:** Spotify bottom navigation, Gmail inbox tabs.

### **Pagination**

- **Purpose / Use:** Split large datasets into manageable pages.
- **Best Practices:**
    - Show next/previous & numeric pages.
    - Indicate active page.
    - Consider infinite scroll for certain apps (feeds).
- **Subcomponents:**
    - Page numbers
    - Prev/Next buttons
    - Jump-to-page input
- **UX Examples:** Google search results, Amazon product listings.

### **Side Drawers / Hamburger Menus**

- **Purpose / Use:** Hide secondary navigation to save space.
- **Best Practices:**
    - Only secondary or infrequent actions.
    - Include labels with icons.
    - Animate open/close for context.
- **Subcomponents:**
    - Menu items
    - Submenu groups
    - Profile section
    - Logout / Settings links
- **UX Examples:** Gmail mobile app, Medium mobile menu.

### **Search Bars / Filters**

- **Purpose / Use:** Quickly find content or refine results.
- **Best Practices:**
    - Place prominently at top.
    - Offer autocomplete and suggestions.
    - Filter applied state visible.
- **Subcomponents:**
    - Input field
    - Clear button
    - Filter dropdowns
    - Search icon / submit button
- **UX Examples:** Airbnb search + filters, Spotify search.

## **2. Forms & Inputs**

### **Text Inputs / Text Fields**

- **Purpose / Use:** Capture user text input.
- **Best Practices:**
    - Always include a label + placeholder.
    - Inline validation; prevent input errors.
    - Support autocomplete, especially for email/addresses.
- **Subcomponents:**
    - Label
    - Input field
    - Placeholder
    - Helper text / error message
    - Clear or action icon
- **UX Examples:** Stripe checkout, LinkedIn profile forms.

### **Text Areas**

- **Purpose / Use:** Multi-line text input for comments, descriptions.
- **Best Practices:**
    - Indicate max characters.
    - Allow resizing.
    - Provide hint text for formatting guidance.
- **Subcomponents:**
    - Label
    - Multi-line input field
    - Character counter
    - Error / validation message
- **UX Examples:** Twitter reply box, GitHub issue description.

### **Dropdowns / Select Menus**

- **Purpose / Use:** Choose one option from a list.
- **Best Practices:**
    - Limit options for better usability.
    - Default selection optional.
    - Support search for long lists.
- **Subcomponents:**
    - Trigger / label
    - Option list
    - Scrollbar / pagination (for long lists)
    - Icons (optional)
- **UX Examples:** Shopify product variant selector, Google Forms dropdown.

### **Checkboxes**

- **Purpose / Use:** Allow multiple selections.
- **Best Practices:**
    - Group related items.
    - Ensure label is clickable.
    - Provide “Select all” option if multiple choices.
- **Subcomponents:**
    - Checkbox box
    - Label
    - Helper text
- **UX Examples:** Gmail multi-select labels, Trello task labels.

### **Radio Buttons**

- **Purpose / Use:** Select a single option from a group.
- **Best Practices:**
    - Show all options at once.
    - Clearly differentiate choices.
    - Avoid long lists.
- **Subcomponents:**
    - Radio circle
    - Label
- **UX Examples:** SurveyMonkey questions, Spotify plan selection.

### **Toggle Switches**

- **Purpose / Use:** Binary on/off settings.
- **Best Practices:**
    - Use for immediate action, not navigation.
    - Label ON/OFF clearly.
    - Maintain state persistence.
- **Subcomponents:**
    - Track
    - Thumb
    - Label
- **UX Examples:** iOS settings toggles, Slack notification preferences.

### **Date & Time Pickers**

- **Purpose / Use:** Select date/time without typing errors.
- **Best Practices:**
    - Include calendar for date.
    - Support manual input.
    - Validate input format.
- **Subcomponents:**
    - Input field
    - Calendar popup / dropdown
    - Time selector
    - Clear / today button
- **UX Examples:** Google Calendar, Booking.com date selector.

### **File Upload / Drag & Drop**

- **Purpose / Use:** Allow users to upload files easily.
- **Best Practices:**
    - Accept only valid formats.
    - Show progress and error messages.
    - Allow multiple files when applicable.
- **Subcomponents:**
    - Drag area / upload button
    - File preview
    - Progress bar
    - Remove/delete button
- **UX Examples:** Gmail attachment, Notion file uploads.

### **Sliders / Range Inputs**

- **Purpose / Use:** Select a value from a range.
- **Best Practices:**
    - Show min/max labels.
    - Display current value.
    - Use large enough handle for touch devices.
- **Subcomponents:**
    - Track
    - Thumb / handle
    - Labels (min, max, current)
- **UX Examples:** YouTube volume control, Google Ads bid range.

### **Autocomplete / Suggestions**

- **Purpose / Use:** Speed up typing and reduce errors.
- **Best Practices:**
    - Provide relevant suggestions.
    - Highlight matches.
    - Allow free input if needed.
- **Subcomponents:**
    - Input field
    - Suggestion list
    - Highlighted matches
- **UX Examples:** Gmail autocomplete, Google search suggestions.

### **Form Validation / Error Messages**

- **Purpose / Use:** Guide users to correct input errors.
- **Best Practices:**

    - Error icon
    - Text message
    - Optional tooltip or helper text
- **UX Examples:** Stripe checkout, LinkedIn profile forms.

## **4. Actions & Controls**

### **Buttons**

- **Purpose / Use:** Trigger actions like submitting forms, navigating, or performing tasks.
- **Best Practices:**
    - Distinguish primary vs secondary vs tertiary actions using color, size, or style.
    - Label clearly with action verbs (“Submit,” “Save,” “Delete”).
    - Ensure touch-friendly size (44–48px minimum).
- **Subcomponents:**
    - Button container / background
    - Label text
    - Icon (optional)
    - Hover / active / disabled states
- **UX Examples:** Stripe checkout buttons, Gmail “Compose” button.

### **Context Menus / Dropdown Actions**

- **Purpose / Use:** Show secondary actions related to a selected item.
- **Best Practices:**
    - Show relevant options only.
    - Highlight active/hovered items.
    - Close menu on outside click or Esc.
- **Subcomponents:**
    - Trigger button / icon
    - Menu list
    - Menu items (text + icon optional)
- **UX Examples:** Google Docs right-click menu, Trello card menu.

### **Sort & Filter Controls**

- **UX Examples:** Airbnb search filters, Amazon product filters.

### **Drag & Drop Handles**

- **Purpose / Use:** Enable reordering or moving items.

### **Undo / Redo / History**

- **Purpose / Use:** Allow users to revert or redo actions.
